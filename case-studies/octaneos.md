# Case study — Traceable vehicle-data reports

**Problem:** turn a supported telemetry file into an inspectable report while preserving provenance and preventing a statistical deviation from becoming an unsupported diagnosis.

**Approach:** CSV contract/quality checks, normalized signals, explicit model mode, deterministic evidence/rules, saved report snapshots and separate technician review. Local execution keeps a demonstration usable without a cloud AI dependency.

**Contribution:** Wajhudeen leads product definition and integration of an AI-assisted independent prototype. Recovered source and archive lineage are recorded. No team member's institutional invention is reassigned by this portfolio.

**Implementation evidence:** FastAPI backend, React/TypeScript frontend, PostgreSQL schema/policies, local PGlite toolchain, automated tests, telemetry charts and demonstration screenshots. Local 0.2 is the latest recovered complete source snapshot.

**Result boundary:** current consolidation verification is in the OctaneOS repository. Historical VED training reports 76.33% run detection on controlled synthetic perturbations and 13.01% normal-window FPR. The authentic frozen artifact is absent; those metrics do not describe the current fallback. They do not establish real motorcycle diagnosis.

**Decision learned:** model availability, input capability and source classification belong in the report. Missing hardware data cannot be repaired with a confident explanation.

**Next:** a versioned SAN adapter and genuine bench-data handoff, followed separately by model-artifact recovery or a fresh reproducible training run.
